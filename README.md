# Jellywebb UI Framework (JUF)

**Jellywebb's cross-platform design standard, design language, and reusable UI implementation framework.**

JUF defines how Jellywebb products should look, behave, communicate, and remain accessible across platforms. Products should feel related without being forced into identical layouts.

## Design language

**Jellywebb Continuum** is the proposed name for JUF's visual and interaction language. Its direction is balanced: premium-interface refinement, enterprise-level functionality, and a distinctive Jellywebb identity.

## What JUF covers

- **Constitution:** principles, requirements, exceptions, and governance.
- **Foundations:** tokens, typography, color, spacing, motion, elevation, and themes.
- **Components:** accessible, reusable interface building blocks.
- **Patterns:** recurring workflows such as forms, tables, filters, dashboards, onboarding, and transaction history.
- **Platform implementations:** shared principles with implementation-specific guidance, beginning with web and React.
- **AI guidance:** rules for AI-assisted design and code generation.

## Core principles

1. Unity without uniformity.
2. Clarity before decoration.
3. Consistency by default.
4. Function determines form.
5. Accessibility is foundational.
6. Responsive behaviour is designed, not patched in.
7. Every meaningful state is communicated.
8. AI-generated work follows the same standard.
9. Changes are governed and documented.
10. Originality over imitation.

## Status

JUF is in its **foundation and specification phase**. Principles and example values in this repository are proposals until explicitly approved. No existing Jellywebb product is required to adopt JUF until a deliberate integration is planned.

## Roadmap

1. Establish the constitution and governance.
2. Define and validate the visual foundation.
3. Build the framework-neutral token layer.
4. Implement shared web components in React and TypeScript.
5. Validate components through accessible examples and tests.
6. Pilot JUF in a selected product without unrelated refactors.
7. Expand to other products and platforms based on evidence.

See the [constitution](constitution/README.md), [design-token foundations](design-tokens/README.md), [implementation roadmap](documentation/ROADMAP.md), and [AI guidelines](AI_GUIDELINES.md).

## Contribution and control

JUF is intended to remain owner-controlled. Public visibility lets people read and fork the repository; it does not grant permission to push directly to the official repository. Proposed contributions can be reviewed before acceptance.

Public visibility does not itself define a software licence. Licensing and reuse terms remain a separate decision.
